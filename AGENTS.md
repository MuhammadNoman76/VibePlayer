## What this is
VibePlayer is a free Windows media player with a YouTube-style interface, built in C#/WPF on LibVLC 3.0.24 through LibVLCSharp 3.10.1.
- Owner: Muhammad Noman (https://github.com/MuhammadNoman76/VibePlayer).
- Website: https://www.nomanshafiq.com/vibeplayer/ (download page) and https://www.nomanshafiq.com/blog/vibeplayer/ (article). The site lives in a separate repo: `D:\Work\nomanshafiq-portfolio`.
- Signature features: skip mode (mark parts of a video to skip, remembered per file, file never edited), hold the right side for 2x, wheel on the bar seeks 5 s, wheel on the video changes volume, Ctrl + wheel changes brightness, resume for long videos, multi-window choice, 81 media file types, automatic updates.

## Layout
- `src/VibePlayer/` holds the app.
  - `Core/`: settings, engine, playlist, instance manager, `Updater.cs`, and the compat helpers `Compat.cs`, `LegacyPolyfills.cs` and `MathEx.cs`.
  - `Views/`: `PlayerView.xaml(.cs)` (the main UI, settings menu built in code via `MenuRow`), `PlayerView.Updates.cs`, and the dialogs.
  - `Interop/`: Win32 P/Invoke.
  - `Themes/`: `Controls.xaml` and `Icons.xaml`.
- `installer/VibePlayer.iss`: one Inno Setup script for every edition (`/DEdition=`, `/DAppVersion=`). `associations.iss` is generated by `build.ps1`; don't edit it by hand.
- `build.ps1`: builds every edition and writes `dist/` and `SHA256SUMS.txt`.
- `release/`: the published installers plus `SHA256SUMS.txt`. Download links point here.
- `publish/` and `dist/` are build output (git-ignored).

## Editions (one codebase)
| Edition | Target | Installer |
|---|---|---|
| x64 | net10.0-windows, win-x64, self-contained | `VibePlayer-Setup-<ver>-x64.exe` (Windows 10/11) |
| arm64 | net10.0-windows, win-arm64, self-contained | `-arm64.exe` |
| x86 | net10.0-windows, win-x86, self-contained | `-x86.exe` (32-bit Windows 10) |
| win7-8 | net48 AnyCPU, both x64 and x86 libvlc; the installer installs the matching one | `-win7-8.exe` (Windows 7 SP1 / 8.1; needs .NET Framework 4.8) |

- The edition is embedded at build time (AssemblyMetadata "Edition") and the updater uses it.
- Keep the same Inno AppId for every edition.
- Each installer must stay under 100 MB (GitHub's file limit).

## Compatibility rules (don't break)
- The code must compile for both net10.0-windows and net48. Use `Compat`, `MathEx.Clamp`, the polyfills, and the net48 `OpenFolderDialog` replacement.
- No `Math.Clamp`, `Environment.ProcessPath` or `File.Move(…, true)` directly.
- 32-bit: never import `GetWindowLongPtrW`/`SetWindowLongPtrW` directly; use the `IntPtr.Size` wrappers in `Interop/Native.cs`.
- Windows 7/8.1: guard Windows 10-only APIs (OS version checks or catching `EntryPointNotFoundException`).
- The libvlc folder follows the process CPU (`win-x64`, `win-x86` or `win-arm64`).

## Build and release
1. Bump `<Version>` in `src/VibePlayer/VibePlayer.csproj`.
2. Build: `powershell -ExecutionPolicy Bypass -File build.ps1 -Version X.Y.Z` (all editions). The .NET SDK is at `%LOCALAPPDATA%\Microsoft\dotnet\dotnet.exe`; Inno Setup 6 is at `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`.
3. Replace the installers in `release/` with the new ones and their `SHA256SUMS.txt`.
4. Commit and push this repo first, so the download links exist.
5. In the website repo:
   - update `src/data/vibeplayer.ts` (version, released date, editions with exact bytes and SHA-256);
   - update `public/updates/vibeplayer.json` (the update feed: version, released, notes, per-edition url/sha256/size);
   - run `npm run verify`, then commit and push. A test fails if the feed and the data file disagree.

## Automatic updates
- The app reads `https://www.nomanshafiq.com/updates/vibeplayer.json` about 10 s after start, then at most once every 24 h. `VIBEPLAYER_UPDATE_URL` overrides the feed URL for testing.
- When a newer version is available it shows a card with Update now, Later and Skip this version.
- Update now:
  - downloads this edition's installer to `%TEMP%\VibePlayer-Update` and checks its size and SHA-256;
  - runs the installer silently with `/RELAUNCH=1`, plus `/CURRENTUSER` or `/ALLUSERS` and `/DIR`, then exits;
  - the installer removes the old program files and relaunches the app, and leftover installers are cleaned up on the next start.
- Users on versions before 1.0.2 have no updater and must install once by hand.

## Testing on the owner's PC (be careful)
- The owner uses VibePlayer daily. Check that no VibePlayer process is running before launching test builds, and never pop windows over a full-screen app.
- Back up `%APPDATA%\VibePlayer` and `%APPDATA%\vlc` before tests and restore them exactly afterwards.
- Don't touch the owner's machine-wide install in Program Files or their file associations. Test installers per-user in a scratch folder (`/CURRENTUSER /DIR=… /TASKS=""`), then uninstall.
